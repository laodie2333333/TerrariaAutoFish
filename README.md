# TerrariaAutoFish · 泰拉瑞亚后台自动钓鱼

Windows 中文界面的自动钓鱼启动器，适配 **Steam 原版 Terraria 1.4.5.8**。工具版本 **0.2.0**。

通过启动器加载本机已安装的游戏，读取自己的鱼漂咬钩状态，调用正常收杆、抛竿流程。切到其他窗口时不占用系统鼠标，不向其他软件发送按键或点击。

> 本工具属于游戏自动化辅助，运行期间会给游戏安装内存补丁。单人使用由玩家自行决定；联机使用请遵守服务器规则。没有修改钓鱼力、掉落表、鱼饵消耗或断线规则。

## 下载与使用

发布后请从仓库 **Releases** 下载 `TerrariaAutoFish-1.4.5.8.zip`，完整解压后运行 `TerrariaAutoFish.exe`。EXE、DLL 和 `.exe.config` 必须保留在同一目录。GitHub 的 **Code → Download ZIP** 下载的是源码，需要先编译。

运行需要 Windows、.NET Framework 4.8、Steam 及正版 Terraria 1.4.5.8 已安装的 XNA 4.0。不需要 Python、OpenCV、tModLoader 或 .NET 10 SDK。

1. 保存并退出当前 Terraria，保持 Steam 登录并运行。
2. 打开工具，确认自动识别的 `Terraria.exe` 路径，点击“启动游戏”。
3. 进入世界，在安全的钓鱼位置手持钓竿、准备鱼饵，**手动向水面抛一次竿**，记录抛竿方向。
4. 在游戏中按 **F8**，或回到面板点击“开始接管”。之后可切换到其他窗口。
5. 按 **F9** 随时请求停止；F8 在游戏前台时也可切换开始 / 停止。

面板最小化进入托盘并继续挂机。**点击关闭按钮会请求停止钓鱼并隐藏面板**，游戏仍继续运行；请先在游戏中保存退出，再关闭工具。游戏再次启动需要重新打开启动器。快捷键被占用时可使用面板或托盘按钮。

停止请求在游戏下一次更新时执行。世界暂停、系统休眠或游戏线程卡住时，程序无法继续钓鱼；界面会提示更新中断，恢复后处理停止请求。建议先用窗口化或无边框、观察几个完整循环后再切出窗口。

## 0.2.0 改进

- **防止连续空挂**：默认连续 3 次等待超时后停止，可设为 1～20 次。正常咬钩收杆重置连续计数。超时并不代表已识别具体原因，需检查落点、水量及岩浆钓鱼条件。
- **鱼漂返回检查**：发起收线后等待鱼漂完全消失；超过 15 秒未返回则停止，不重复发起收线。
- **停止通知**：自动停止时发送托盘通知，可在面板关闭；Windows 通知设置可能影响是否显示。
- **持久日志**：每次打开面板创建 UTF-8 会话日志，记录开始、收杆、重抛、超时、停止原因和会话摘要，单文件达到 5 MiB 后续写新文件。
- **会话状态**：显示本次挂机时长、连续 / 累计超时、世界更新频率。移动超过 6 格后清除旧抛竿方向，需重新手动抛竿。

设置在下次开始钓鱼时应用，通知开关立即生效。旧版设置会保留，新增选项使用默认值。日志位于 `%LOCALAPPDATA%\TerrariaAutoFish\Logs`，面板和托盘都可以打开；日志不会自动上传，历史日志可按需要自行清理。

## 默认设置和停止条件

| 设置 | 默认值 | 含义 |
|---|---|---|
| 重抛间隔 | 800 ms | 鱼漂返回并且物品可用后才会重抛 |
| 无咬钩超时 | 180 秒 | 单次等待超时后收线重抛 |
| 连续超时停止 | 3 次 | 避免落点或钓鱼条件不满足时无限重试 |
| 低生命停止 | 25% | 生命不高于阈值时停止，设为 0 关闭 |
| 跳过怪物咬钩 | 开启 | 等待怪物咬钩结束，拒绝优先使用松露虫 |
| 主背包无空格时停止 | 开启 | 保守判断，没有空格就停止，尚未精确判断堆叠空间 |
| 自动停止通知 | 开启 | 手动停止不弹该通知 |

角色死亡、换下 / 更换钓竿、离开世界、打开背包 / 地图 / 交互界面、鱼饵耗尽、移动超过 6 格、连续抛竿失败、连续等待超时、收线卡住均会停止。停止钓鱼**不会暂停世界或退出游戏**。

多鱼漂时，只要任一鱼漂钩住怪物就暂不收杆，这也可能错过同时咬钩的鱼。“收杆次数”是操作数，不是成功入包数量；断线和游戏规则仍会影响实际收获。目前不提供自动喝药、整理背包、战斗或交付渔夫任务。

## 从源码构建

安装游戏及上述运行依赖后，在项目目录运行 PowerShell：

```powershell
# 无需游戏即可运行的逻辑和日志测试：
powershell -ExecutionPolicy Bypass -File .\test.ps1

# 自动查找 Steam 游戏库，编译并检查启动初始化流程：
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Check

# 手动指定安装路径：
powershell -ExecutionPolicy Bypass -File .\build.ps1 -GamePath 'E:\SteamLibrary\steamapps\common\Terraria\Terraria.exe' -Check

# 可选：真实主菜单加载，独立存档目录中观察 30 次更新后退出：
powershell -ExecutionPolicy Bypass -File .\test-startup.ps1
```

构建使用 Windows 自带 C# 编译器，输出到 `dist/`，首次从 NuGet 下载 Harmony 2.4.2。`-Check` 使用独立目录，执行原版入口并验证路径和补丁，然后拦截窗口创建。GitHub Actions 只运行无需游戏的逻辑和日志测试，不下载游戏文件。

| 目录 / 文件 | 用途 |
|---|---|
| `src/` | 控制面板、游戏加载器、钓鱼状态机、日志 |
| `tests/` | 逻辑、日志和真实启动检查 |
| `tools/` | 游戏库查找、大内存标志、图标开发工具 |
| `assets/` | 金钓竿应用图标及尺寸变体 |
| `docs/` | GitHub 上传指南和现场验证清单 |
| `dist/` | 编译成品与便携 ZIP，Git 忽略 |
| `.local/`、`.tools/`、`.venv/` | 本地缓存与开发环境，Git 忽略，不能作为源码上传 |

## 实现原理

启动器进程加载用户安装的原版游戏，通过 Harmony 在运行期间给更新、物品使用和抛竿方法增加逻辑。程序读取本地玩家鱼漂的 `ai` / `localAI` 状态，在正常物品使用流程中临时设置使用钓竿和瞄准坐标，执行后恢复内部输入状态，不操作系统鼠标。

补丁安装在 `Program.InitializeConsoleOutput` 检查点，此时存档路径已设置。XNA 的 `TitleLocation` 在运行期间指向游戏安装目录，并验证着色器资源可读取；生成的 x86 宿主设置与原版一致的 `LARGE_ADDRESS_AWARE` 标志。没有改写原版 EXE，不注入已经运行的游戏进程；角色和世界仍通过游戏正常流程保存。
